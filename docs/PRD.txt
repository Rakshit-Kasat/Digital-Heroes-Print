Project overview. § 01 · THE BRIEF

Build a custom web-to-print platform for a multi-division print business. Customers

configure, design, proof, and order print products online; staff run every job from quote to

production in one place.

PRD is a subscription-free, transactional web-to-print platform for a print house running six divisions under
one roof: labels & stickers, race & event numbers, MTB boards, stamps, trophies, and laser-cut work. It
must feel like a modern, Shopify-grade storefront, but do real production work the moment an order lands --
not stop at an artwork upload.

Customers will be able to:

   Browse the six product ranges and see live examples of real print work.

Configure a product (size, material, quantity) and get an instant price.

Design artwork in-browser or upload finished files, then approve a proof.

Pay, track the order, and reorder in one click from saved designs.          02 1OWNED PLATFORM

CONFIGURATION RULES

   Parameter-driven products. A single product models many variants -- do not create one SKU per size.
   Dynamic sizing. Size, material, orientation and quantity are configured, not pre-listed.
   Per-placeholder fitting rules. Shrink-to-fit, tracking, and min/max font size so content always fits the print
   area.

Why it matters.

One flexible product replaces dozens of near-duplicate SKUs, cutting catalogue bloat and admin overhead in
equal measure.

Pricing & checkout. 05 § 05 · PRICING & CHECKOUT

§ 05 · MONEY IN

Transactional, not subscription. The platform earns per order, priced live by an instant
calculator -- no quote forms, no waiting.

Pricing engine    Live per-unit pricing by product, size and quantity. Price updates instantly as
                  options change.

Volume discounts  Applied automatically from a defined quantity floor (e.g. from 100 units).
Tax               VAT-inclusive totals shown at a glance; final price confirmed at checkout with no
                  surprises.

Gateway           Stripe or an equivalent PCI-compliant provider via an integrated checkout.
Order capture     Payment and full order data written to the structured backend against the customer
                  account.

Design inside 06 Accounting-ready
                  Order records structured for clean export to accounting (Xero-ready data shape).

No subscription tax.

Revenue is per order. Do not build a recurring-billing model -- build a clean, fast, per-order checkout instead.

The print-file engine. 07 § 07 · PRINT-FILE & VARIABLE DATA

§ 07 · WHERE IT EARNS ITS KEEP

This is the part that separates a real web-to-print platform from a generic store: turning an
approved design into a file a printer can actually run.

PRODUCTION OUTPUT

   Automated print-ready files. Per-order high-resolution PDF and PNG, with defined bleed and resolution
   per product type.
   CSV variable-data merge. Server-side processing generates one artwork file per row for race numbers
   and bulk jobs -- no manual tweaking.
   Per-placeholder fitting. Shrink-to-fit, horizontal tracking and min/max font size so variable content always
   fits.

STRUCTURE BY DEFAULT

Outputs follow a predictable naming convention and are grouped in order-based directories:

 OrderID_ProductType_Date_Output

  Server-side where it counts.

   Print-file generation and CSV merge must run on the server, keeping heavy processing off the customer's
   device and consistent across every order.

08 § 08 · PROOF & VERSION CONTROL

Versioning that holds up.

Every proof revision is logged, so there is never a question of which file the customer
actually approved.

   Versioned proofs. Each revision is stored as v1, v2 ... against the order.
   Approval logs. Record who approved which version and when.
   Change requests. Customers can request revisions before approving the final proof.
   Approval gate. Print-ready files unlock only once a proof is approved.
